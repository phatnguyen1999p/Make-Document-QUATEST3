# V9 — Đưa source lên ổ Z cho nhiều máy cùng dùng (kho git gốc trên Z, mỗi máy một bản clone)

- **Trạng thái:** Open (12/11/2026, Claude Code) — phần một máy đã xong; phần nhiều máy chờ người dùng quyết
- **Cần người dùng quyết:** dùng kho git trên Z (đề xuất) hay chạy thẳng thư mục trên Z; khi nào làm

## Mô tả

Người dùng (12/11/2026): muốn để source trên ổ mạng Z cho nhiều máy dùng chung và nhiều Claude chạy hồ sơ; sau đó chốt "Tối ưu trước cái hiện tại để chạy riêng trên máy t đã" → phần một máy đã làm (context tách file + khóa, AGENTS mục 16). Phần nhiều máy **chưa làm, chờ người dùng quyết**.

Thiết kế đã đề xuất (chưa được duyệt):

- Kho git gốc trên Z, mỗi máy một bản clone trên ổ C; Claude `git pull` đầu phiên, `commit` + `push` cuối task. Không máy nào chạy trực tiếp trên Z (sửa dở một file Core trên Z làm máy khác dựng lỗi; Python / Word / Excel chạy qua mạng chậm).
- `Input\<6 số>\` (1,3 GB) không vào git — để trên từng máy, nguồn và đích vẫn là thư mục hồ sơ trên Z.
- `HieuChuan\` (969 MB), UpChungThu, DrawIO Tool: một bản chỉ đọc trên Z, mỗi máy trỏ bằng biến môi trường.
- Khóa hồ sơ phải nằm ở chỗ mọi máy cùng thấy: đặt `LAMKQ_CONTEXT_DIR` (đã có trong `context.py`) hoặc riêng thư mục `_khoa` lên Z.

Việc phải làm kèm khi lên nhiều máy:

- Sổ `ai_files.json` đang nằm trong `Input\<6 số>\ThucHien\_checkpoint\` (không lên Z) → máy khác mở lại hồ sơ sẽ thấy mọi file trên Z là `[Z EDITED]`; cần để sổ đi theo hồ sơ.
- Gỡ đường dẫn `C:\Users\phat.nt\...` ghi cứng: 18 chỗ trong 14 file (quan trọng: `Core/Services/upchungthu_bridge.py`, `Core/Tools/drawio_layout.py`; còn lại trong `Core/Source Code/`).
- ID lỗi `E<n>` / việc `V<n>` cấp theo số kế tiếp chỉ an toàn khi mọi phiên thấy cùng một thư mục `Context/Viec`.
- Bộ nhớ riêng của Claude nằm theo từng máy → quy tắc bền phải nằm trong `AGENTS.md`.
- Workspace hiện chưa là kho git (máy này có git 2.56).
